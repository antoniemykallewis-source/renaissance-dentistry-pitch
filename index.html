02 / The opportunityPublic-page review / October 20, 2026

The photos show change. The story is missing.

The strongest opportunity is already on the site: explain what the practice did, why that plan made sense, and what a patient should ask about next.

Case presentation01

“Case 1” is not a treatment story.

The Smile Gallery labels cases by number and before/after status. The displayed entries do not explain the treatment, patient goal or elapsed time. Visitors can see a difference without understanding the care behind it.

Smile Gallery / seven displayed numbered cases ↗
Vessel would

Turn selected, consented cases into concise stories: the goal, clinical plan, treatment, timing and limitations. Add practitioner-approved context and relevant next steps.

Appointment journey02

The request needs a clearer expectation.

The appointment form says a submission does not secure an appointment and the team will contact the patient. It asks for a preferred time of day, but the visible explanation gives no expected response window.

Appointment form / callback process ↗
Vessel would

Keep the honest request language. Add a realistic response expectation, an urgent-care alternative and a confirmation that explains the next step. Coordinate it with the team’s workflow.

First impression03

Five stories compete in the hero.

The homepage rotates through cosmetic, Invisalign, restorative, airway and eco-friendly messages. The slide subheading repeats a general Folsom-practice description rather than making each pathway distinct.

Homepage / rotating treatment slides ↗
Vessel would

Choose one primary first-screen story. Move the other services into a stable, easy-to-scan set of pathways, with real practice imagery and an obvious consultation action.

Make the bio easier to absorb

The doctor’s training and education-first approach are substantial. Use a short introduction video and a clearer hierarchy to make those strengths easier to understand.

Connect cases to services

Give gallery stories a named treatment and a corresponding service page. Help visitors move from the example they like to the information they need.

Align the gallery labels

The homepage’s Case 7 preview uses image alternatives referring to Case 8. Check visible labels and image descriptions against the approved case record.

What we would validate before scaling

Mobile speed + usability

Benchmark the current site on a controlled mobile profile, then test image loading, navigation and the first useful action. No fresh Lighthouse or Core Web Vitals score is asserted in this proposal.

Google profile + reviews

Confirm the owner-approved name, address, hours and booking link against the live profile. Review recent feedback and response handling. No directory count is presented as a fresh Google-verified total.

Social content + dates

Review the linked official profiles, recent post dates, formats and useful engagement with account access. A quiet website blog or missing embedded video does not establish that social content is inactive.

Ads + measurement

Inspect current campaign ownership, conversion definitions and consent behavior. Public page tags alone cannot prove active spend, missing tracking or successful attribution. Preserve working tools and test the actual handoff.

Search + AI discovery

Use Search Console and a repeatable local query set to establish a baseline. Improve practitioner, service and case context. We do not infer ranking failure or universal AI absence from a single search snapshot.

Booking + follow-up

With the team, test an agreed inquiry from click through confirmation and staff response. This public review did not submit patient information, place calls or make appointments.

The first phase confirms access, approvals and measurement before any paid launch. Proposed work and filming remain subject to the practice’s clinical review, patient permissions, existing vendor responsibilities and an agreed scope.
